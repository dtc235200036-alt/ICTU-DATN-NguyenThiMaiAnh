</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/accounts | Admin operations reachable by any authenticated user who guesses the URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12 | Elevation of privilege | /api/accounts/* | high | mitigate | Router-level require_role(BO_MON); test_accounts_rbac asserts 403 for SV and GV on all five endpoints and that the target row is unchanged |
| T-02-13 | Elevation of privilege | account create/update | medium | mitigate | vai_tro limited to SINH_VIEN/GIANG_VIEN in AccountCreate; update/lock/unlock return 404 for BO_MON targets, so no admin can be created or altered via the API |
| T-02-14 | Information disclosure | AccountOut responses | medium | mitigate | Response schema omits mat_khau_bam; verify asserts no password field in the list response through Apache |
| T-02-15 | Spoofing | weak passwords set by admin | low | mitigate | mat_khau 8–128 chars, ≤ 72 bytes (bcrypt limit), hashed with cost 12 |
