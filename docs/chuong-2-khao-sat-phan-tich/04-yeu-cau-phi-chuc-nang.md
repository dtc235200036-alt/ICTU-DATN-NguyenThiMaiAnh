## 2.4. Yêu cầu phi chức năng

> **Mã PI:** 1.2 — **Yêu cầu:** ANLS-04

Bảng dưới đây liệt kê các yêu cầu phi chức năng theo 8 nhóm: Bảo mật, Phân quyền, Hiệu năng, Thời gian phản hồi kiểm tra trùng lặp, Dữ liệu và tiếng Việt, Triển khai, Tương thích, Dữ liệu thử nghiệm. Mỗi hàng có một ngưỡng đo được cụ thể (số hoặc nhị phân đạt/không đạt) và một cách kiểm chứng cụ thể, để tránh yêu cầu chung chung không kiểm tra được.

| Mã | Nhóm | Yêu cầu | Ngưỡng đo được | Cách kiểm chứng | Nguồn |
|----|------|---------|-----------------|-------------------|-------|
| NFR-01 | Triển khai | HTTPS qua Apache reverse proxy | 100% request HTTP tới cổng 80 được chuyển hướng (redirect) sang HTTPS cổng 443 | Kiểm tra cấu hình Apache (`VirtualHost` cổng 80 có `Redirect permanent`); `curl -I http://<host>/` trả mã 301/302 sang `https://` | DEPL-02 |
| NFR-02 | Bảo mật | Mật khẩu được băm trước khi lưu | Mật khẩu băm bằng bcrypt với cost factor ≥ 12; không có mật khẩu dạng plain-text hay mật khẩu xuất hiện trong log ứng dụng | Đọc trực tiếp cột mật khẩu trong CSDL (phải là chuỗi băm bcrypt `$2b$12$...` trở lên); grep log ứng dụng không có chuỗi mật khẩu | AUTH-01 |
| NFR-03 | Bảo mật | JWT ký và có thời hạn | JWT ký bằng secret key đọc từ biến môi trường (không hardcode trong mã nguồn); thời hạn token có số cụ thể (đề xuất 8 giờ với access token); token hết hạn khi gọi API phải trả 401 | Test gọi API trực tiếp bằng token đã hết hạn (giả lập bằng token có `exp` trong quá khứ), kỳ vọng HTTP 401 | AUTH-01, AUTH-02 |
| NFR-04 | Phân quyền | Kiểm tra vai trò và quyền sở hữu phía server trên mọi API | 100% API (trừ đăng nhập) kiểm tra JWT hợp lệ và vai trò phía server; gọi API với vai trò sai trả 403; gọi API để truy cập dữ liệu không thuộc quyền sở hữu của người dùng (vd. GVHD xem báo cáo SV không phải mình hướng dẫn) bị từ chối | Test gọi API trực tiếp (không qua UI) với JWT hợp lệ nhưng sai vai trò/không sở hữu dữ liệu, kỳ vọng HTTP 403 cho toàn bộ endpoint được liệt kê trong OpenAPI docs của Web API | AUTH-03 |
| NFR-05 | Phân quyền | Tài khoản bị khóa không đăng nhập được | Tài khoản ở trạng thái "khóa" nhận HTTP 401/403 khi gọi API đăng nhập, kể cả khi nhập đúng mật khẩu | Test gọi API đăng nhập trực tiếp với một tài khoản đã được Bộ môn khóa | AUTH-04 |
| NFR-06 | Bảo mật | Kiểm tra file upload theo nội dung, không theo đuôi file | File đề cương/báo cáo chỉ được chấp nhận nếu nội dung nhị phân (magic bytes) khớp DOCX hoặc PDF, bất kể đuôi file khai báo; dung lượng tối đa 20 MB, áp dụng ở cả tầng Apache (`LimitRequestBody`) và tầng Web API (kiểm tra `Content-Length`/kích thước thực tế); tên file lưu trữ trên server do server sinh ra (không dùng tên file người dùng gửi lên) | Đổi đuôi một file `.exe` thành `.docx` rồi gọi API upload trực tiếp, kỳ vọng bị từ chối; upload file > 20 MB, kỳ vọng bị từ chối ở cả Apache và Web API | OUTL-01, DEFN-01 |
| NFR-07 | Bảo mật | Dịch vụ AI không có đường public | Dịch vụ AI (check-title/check-document/ingest) không được cấu hình route qua Apache ra Internet; request tới dịch vụ AI thiếu API key nội bộ trả HTTP 401 | Kiểm tra cấu hình Apache không có `ProxyPass` trỏ tới cổng dịch vụ AI; gọi trực tiếp endpoint dịch vụ AI (qua mạng nội bộ, không qua Apache) mà không kèm header API key, kỳ vọng 401 | AISV-01 |
| NFR-08 | Thời gian phản hồi kiểm tra trùng lặp | Kiểm tra trùng tên đề tài | Thời gian phản hồi (P95) của endpoint check-title ≤ 5 giây, đo trên server với kho đã seed đủ 300 đề tài | Gọi trực tiếp API check-title 20 lần liên tiếp với kho 300 đề tài đã ingest, đo P95 thời gian phản hồi trên server (không tính độ trễ mạng client) | AISV-03 |
| NFR-09 | Thời gian phản hồi kiểm tra trùng lặp | Kiểm tra trùng lặp tài liệu | Thời gian từ lúc nộp tài liệu đến khi trạng thái chuyển "Hoàn tất" (P95) ≤ 30 giây, đo trên server với kho đã seed đủ 300 đề tài và 50 file | Nộp lần lượt 20 file thử nghiệm (kho đã seed đủ), đo thời gian từ timestamp nộp đến timestamp trạng thái "Hoàn tất" trong CSDL, tính P95 | AISV-04, AISV-06 |
| NFR-10 | Hiệu năng | Nộp file không bị chặn bởi kiểm tra trùng lặp | API nộp đề cương/báo cáo trả phản hồi thành công trong ≤ 2 giây kể cả khi kiểm tra trùng lặp đang chạy nền (không đồng bộ chờ kết quả AI) | Đo thời gian phản hồi của API nộp file trực tiếp, độc lập với thời gian dịch vụ AI xử lý xong | AISV-06 |
| NFR-11 | Hiệu năng | Embedding kho tính sẵn lúc ingest | Thao tác ingest một bản ghi mới vào dịch vụ AI không kích hoạt tính lại embedding cho các bản ghi khác đã có trong kho | Đo số lượng lệnh gọi model embedding khi ingest 1 bản ghi mới vào kho đã có N bản ghi — kỳ vọng đúng 1 lần gọi, không phụ thuộc N | AISV-02, REPO-03 |
| NFR-12 | Hiệu năng | Thời gian phản hồi tra cứu/danh sách | Thời gian phản hồi (P95) của API tra cứu kho và API danh sách đề tài ≤ 1 giây, đo trên server với dữ liệu seed đầy đủ (300 đề tài trong kho) | Gọi trực tiếp API danh sách/tra cứu 20 lần với dữ liệu seed đầy đủ, đo P95 thời gian phản hồi trên server | TOPC-04, REPO-02 |
| NFR-13 | Dữ liệu và tiếng Việt | Bảng mã CSDL hỗ trợ tiếng Việt | CSDL MySQL 8 dùng charset `utf8mb4` và collation `utf8mb4_vietnamese_ci` cho toàn bộ bảng/cột văn bản; schema được quản lý bằng migration (Alembic), không sửa tay trực tiếp trên server | Kiểm tra `SHOW CREATE TABLE` cho mọi bảng có cột văn bản; kiểm tra thư mục migration có lịch sử phiên bản khớp với schema hiện tại | DEPL-01 |
| NFR-14 | Dữ liệu và tiếng Việt | Chuẩn hóa Unicode nhất quán | Toàn bộ điểm nhập liệu (tên đề tài, tên người dùng, nội dung đề cương/báo cáo) được chuẩn hóa NFC trước khi lưu và trước khi đưa vào so sánh ngữ nghĩa; cùng một tên nhập ở dạng NFD hoặc NFC phải cho cùng kết quả so sánh trùng lặp | Nhập cùng một chuỗi tiếng Việt ở hai dạng mã hoá Unicode khác nhau (NFC và NFD) qua API, kỳ vọng cả hai được lưu giống hệt nhau và trả cùng tỷ lệ trùng lặp khi so sánh | AISV-02 |
| NFR-15 | Triển khai | Client tĩnh và proxy API | Client React được build và phục vụ dưới dạng file tĩnh; Apache proxy `/api` sang Web API; `ProxyTimeout` của Apache lớn hơn thời gian kiểm tra trùng lặp dài nhất (> 30 giây, đề xuất 60 giây) để không cắt ngang request kiểm tra tài liệu | Kiểm tra cấu hình Apache có `DocumentRoot` trỏ tới thư mục build tĩnh và `ProxyPass /api` sang Web API; kiểm tra giá trị `ProxyTimeout` trong file cấu hình | DEPL-02 |
| NFR-16 | Tương thích | Trình duyệt và độ phân giải hỗ trợ | Giao diện được thiết kế và kiểm thử trên trình duyệt desktop Chrome hoặc Edge phiên bản hiện hành, khung màn hình cố định 1440px; không có yêu cầu tương thích di động/responsive | Mở toàn bộ màn hình chính bằng Chrome/Edge ở độ rộng cửa sổ 1440px, kiểm tra không có phần tử bị cắt hoặc tràn | D-13 |
| NFR-17 | Dữ liệu thử nghiệm | Seed người dùng | Dữ liệu thử nghiệm có đúng 100 tài khoản Sinh viên và 30 tài khoản Giảng viên | Đếm số dòng bảng người dùng theo vai trò sau khi chạy script seed | DATA-01 |
| NFR-18 | Dữ liệu thử nghiệm | Seed đề tài và ingest AI | Dữ liệu thử nghiệm có 300 đề tài thuộc nhiều khóa khác nhau, toàn bộ 300 đề tài đã được ingest vào dịch vụ AI (có embedding) | Đếm số dòng bảng đề tài và số bản ghi có embedding trong dịch vụ AI sau khi chạy script seed, hai số phải bằng nhau | DATA-02 |
| NFR-19 | Dữ liệu thử nghiệm | Seed file trùng lặp có chủ đích | 50 file đề cương/báo cáo thử nghiệm, trong đó có các cặp trùng lặp chủ đích thuộc đủ 4 loại (chép nguyên văn, diễn đạt lại, cùng lĩnh vực khác đề tài, không liên quan), kèm bảng kết quả kiểm chứng ghi rõ cặp nào thuộc loại nào và tỷ lệ trùng kỳ vọng | Đối chiếu bảng kết quả kiểm chứng với kết quả kiểm tra trùng lặp thực tế trả về từ dịch vụ AI cho từng cặp file | DATA-03 |

**Ghi chú:** Các ngưỡng số trong bảng trên (5 giây, 30 giây, 20 MB, 8 giờ, cost factor 12, 1–2 giây...) là **đề xuất dựa trên nghiên cứu tài liệu kỹ thuật (`research/PITFALLS.md`, `research/ARCHITECTURE.md`) và các quyết định thiết kế ban đầu trong `01-CONTEXT.md`**, cần xác nhận lại với GVHD trước khi thi công (Phase 2–4), và sẽ được đo lại thực tế trên dữ liệu seed ở Phase 5 (RPRT-01) để xác nhận hệ thống đạt hay cần điều chỉnh ngưỡng.
